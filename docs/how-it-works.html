@nicolopadovan/analytics-consent-manager

How the package decides what loads, when, and why. Based on 1.0.0-rc.1 source (packages/analytics-consent-manager/src).

1. The three layers

Consent engine core/consent-engine.ts

Holds the visitor's choice. Nothing else.

  • { preferences, analytics, marketing } or null (= not asked yet)
  • Reads/writes a storage adapter (default: localStorage["npcm_consent"], migrated from the old acm_consent; Scriptie uses a cookie)
  • Syncs with integration adapters (e.g. Shopify Customer Privacy API)
  • Broadcasts npcm:consent DOM event + window.NPCM_CONSENT (plus the old acm:/ACM_ names)
→

Analytics manager core/analytics-manager.ts

Subscribes to the engine and drives every provider through a lifecycle.

  • boot() — nothing happens to providers before this
  • On each consent change: re-evaluates every provider
  • track drops events unless analytics is granted (default), and gives each one an id shared by browser and server
  • Auto-tracking: clicks, scroll depth, time on page
→

Providers providers/*.ts

Small plugins, each with a requiredConsent category and optional hooks:

  • setup — runs at boot, regardless of consent; no network, no cookies
  • consent — runs at boot and on every change, regardless of consent
  • load — injects scripts, once: when its category is granted, or at boot with loadBeforeConsent
  • teardown — runs when consent is withdrawn
  • page / track / identify — only while active; each provider translates the standard event (add_to_cart → Meta's AddToCart)

React layer /react, /ui

<AnalyticsProvider analytics={…}> takes the createAnalytics() instance, boots it (immediately, on idle, or manually) and fires a page view per route · <CookieBanner>/<CookieDialog> give you Accept all / Reject / Customize; useAnalytics() / useConsent() for your own UI. window.NPCM_openConsent() reopens the dialog.

Server /server

createAnalyticsHandler is one route that receives browser events (with server: { endpoint }) and forwards them to Meta CAPI, deduped by event ID. sendServerEvent sends webhook events to GA4 and Meta. Both check the consent sent with each event, hash personal data and read _fbp/_fbc/_ga.

3. A page load, step by step

Engine bootstraps

Reads storage. If empty, asks integration adapters (Shopify). Still nothing → consent is null.

Banner shows

The controller sees null and shows the banner. Providers are untouched so far.

Manager boots

Every provider gets setup() and consent(), with consent still null; those with loadBeforeConsent also get load().

Visitor chooses

Engine saves it, notifies the manager. Providers whose category is now granted get load() (once) and become active.

Tracking flows

Page views and events go only to active providers. Withdrawing consent calls teardown().
