title: ConsentLayer and c15t
description: How ConsentLayer compares with c15t, what each one has that the other does not, and how the two can run together.
---

[c15t](https://c15t.com) is an open-source consent management platform for
JavaScript and the project closest to ConsentLayer. The two overlap, but they
solve different parts of the problem. c15t collects consent: it ships the
banner, stores each choice and loads third-party scripts once they are
allowed. ConsentLayer acts on consent: it loads the analytics providers and
sends your events to them, in the browser and from your server. Its
[banner](/guides/banner/) is an optional entry point, so you can use your own
instead.

This page compares the two as of October 2026. The c15t column is based on
[its repository](https://github.com/c15t/c15t) and
[documentation](https://c15t.com/docs), not on running it; check them for
anything that has changed since.

## What c15t has that ConsentLayer does not

- A consent UI translated into 35 languages, with a theme system. The
  [banner](/guides/banner/) of ConsentLayer is in English, with every string
  overridable and its look set through CSS custom properties or your own
  classes. You translate it yourself.
- A consent platform you don't have to run: hosted consent records with a
  dashboard and audit history. ConsentLayer writes records to your database
  and leaves querying, retention and deletion to you.
- A full IAB TCF and GPP implementation. Its documentation describes using
  Inth's registered CMP ID with the hosted service and its stock IAB
  components; other setups need their own registration with IAB Europe.
  ConsentLayer only reads a CMP's decision.
- Over four times as many integrations, including chat widgets, embeds such as
  YouTube and Google Maps, and pixels for LinkedIn, Reddit, Snapchat, X and
  Microsoft.
- A track record: it is used in production by thousands of sites and
  maintained by a company. ConsentLayer has no production history yet.

Each of these features, including hosted consent records, is on the
[roadmap](/guides/roadmap/#planned).

## What ConsentLayer has that c15t does not

- One tracking API for every provider. `analytics.track('purchase', ...)`
  reaches GA4, Meta, TikTok and PostHog, each in its own format and only while
  its consent category is granted.
- Server-side events. The same events are forwarded to GA4, Meta, TikTok and
  server-side GTM from your server, which can accept only the consent the
  visitor's signed consent cookie proves.
- Support for Solid, SolidStart and Angular, which c15t's documentation does
  not list.
- No runtime dependencies and no backend to host. Consent records are
  optional.

## Using both

c15t can collect consent while ConsentLayer tracks. When c15t runs as an IAB
TCF CMP, the [`tcf()`](/guides/adapters/tcf/) adapter reads its decision and
ConsentLayer follows it. This combination has not been tested; the adapter is
tested against a simulated `__tcfapi`. Without TCF mode, call
[`analytics.consent.update()`](/guides/events/#consent) whenever c15t reports a
change.

Neither project makes a setup comply with a law; see the
[legal notice](/guides/legal/).
