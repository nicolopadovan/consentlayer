consentlayer doesn't ship a banner, so its design, wording and languages stay
yours. `useConsentController()` from `consentlayer/react` provides the state
and actions; the recipe below is a working banner to copy into your app and
restyle. It is the same banner the [Playground](/playground/) runs.

## `useConsentController()`

Call it inside `<AnalyticsProvider>`, which holds the banner's state.

| Field | What it is |
|---|---|
| `ready` | `true` once stored consent has been read. Render nothing before it, so returning visitors don't see the banner flash |
| `bannerVisible` | `true` until the visitor chooses (with `<AnalyticsProvider autoShowBanner>`, the default) |
| `dialogVisible` | the settings dialog is open |
| `prefs`, `setPrefs` | the dialog's draft choices, one per category, saved only by `savePreferences` |
| `acceptAll()` | grants every category and closes both |
| `rejectNonEssential()` | denies every category and closes both |
| `savePreferences()` | saves `prefs` and closes both |
| `openDialog()`, `closeDialog()`, `showBanner()`, `hideBanner()` | visibility |
| `error` | why reading stored consent failed, if it did |

### Reopening the settings

Visitors must be able to change their choice later. Inside React, call
`openDialog()`, as the recipe's "Cookie settings" button does below. Outside
React, for example in a footer rendered by your CMS, call
`window.CONSENTLAYER_openConsent()`. The global's name follows
[`names.prefix`](/guides/names/).

## Recipe

Copy both files, then change the wording and the styles. The dialog shows a
toggle for every category, so `categories` needs a label for each one.
Necessary cookies are always on, so the dialog shows them checked and
disabled. `functional` is the Playground's [custom category](#custom-categories);
delete it unless you declare it.

Render it once inside the provider, and add a way back to the settings:

```tsx
import { AnalyticsProvider, useConsentController } from 'consentlayer/react'
import { ConsentBanner } from './consent-banner'

function CookieSettingsButton() {
  const { openDialog } = useConsentController()
  return <button onClick={openDialog}>Cookie settings</button>
}

<AnalyticsProvider analytics={analytics}>
  {children}
  <ConsentBanner privacyPolicyUrl="/privacy" />
  <CookieSettingsButton />
</AnalyticsProvider>
```

The text is plain strings in your component, so translate it with the i18n
your app already uses.

## Custom categories

`preferences`, `analytics` and `marketing` are built in. To add your own,
declare it for TypeScript and pass it to `createAnalytics`:

```ts
import { createAnalytics, definePlugin, loadScript } from 'consentlayer'

declare module 'consentlayer' {
  interface ConsentCategories {
    functional: true
  }
}

const supportChat = definePlugin({
  id: 'support-chat',
  requiredConsent: 'functional',
  load: () => loadScript('https://chat.example.com/widget.js'),
})

export const analytics = createAnalytics({
  categories: ['functional'],
  providers: [supportChat],
})
```

A custom category works like a built-in one. It is stored, broadcast and sent
to your server; it is denied until granted; "Accept all" grants it and
"Reject non-essential" denies it. Any plugin can require it with
`requiredConsent`, and `analytics.consent.categories` lists every category.

Both steps are needed. Without the declaration, `categories: ['functional']`
and `requiredConsent: 'functional'` don't compile. Without the `categories`
option, the choice is never stored.
